## Summary

Two parallel binaries: `drmon-dap-snes` and `drmon-dap-gen`, each a standalone C++17 DAP adapter
that speaks to VS Code / nvim-dap over stdin/stdout and to MAME over the existing TCP bridge on
`:41816`.  `snesmon`/`genmon` stay functional indefinitely — "two binaries in parallel", not a TUI
deprecation.

```
VS Code / nvim-dap  ←— stdin/stdout DAP ——→  drmon-dap  ←— TCP :41816 ——→  mame_bridge.lua → MAME
```

---

## Architecture

### Why a new binary, not a TUI refactor

The TUI modules (`break.cpp`, `symbol.cpp`, `expr.cpp`, `memory.cpp`, `reg.cpp`,
all of screen/layer/window/gadget) are 40–60% entangled with the `_object`/`_layer`
event loop via `moninc.hpp`.  Surgically separating them would be high-risk and low-return.

**New `drmon-dap` binary** compiles only the clean modules:
- `linux/dap/backend.cpp` — fresh MAME TCP client (no sliomame.cpp dependency;
  avoids the reg.cpp / control.cpp / moninc.hpp chain entirely)
- `linux/dap/session.cpp` — cppdap DAP request handlers
- `linux/dap/breakpoints.cpp` — address breakpoint tracking
- `linux/dap/registers.hpp` — per-system register name/mask tables

cppdap fetched via CMake `FetchContent` at tag `dap-1.58.0-a`.

### Step engine

`backend.cpp` includes a complete 65816 opcode-size table (256 entries).
`snesNextPC()` reads the opcode at PC, adjusts size for M/X flag variants
(immediate operands), handles branches (conditional + unconditional) and
long jumps by computing BOTH possible next addresses, and sends `S <next> [<alt>]`
to the bridge.  Correct for all common SNES code paths.

## Tier 1 DAP surface (complete)

| Request | Implementation |
|---------|---------------|
| `initialize` | Return capabilities; send `InitializedEvent` |
| `attach` | `MameBackend::connect()` (host/port from CLI) |
| `configurationDone` | Start poll thread (50 ms cycle) |
| `setInstructionBreakpoints` | `B+`/`B-` bridge commands; `BreakpointTable::sync()` |
| `continue` | `C` command |
| `pause` | `H` command |
| `next` / `stepIn` | `snesNextPC()` → `S <addr>` |
| `threads` | Static: `[{id:1, name:"maincpu"}]` |
| `stackTrace` | One frame at current PCL |
| `scopes` | One scope: "Registers" (ref=1) |
| `variables` | All registers from `G` response; each sets `memoryReference` → VS Code Memory Inspector icon |
| `readMemory` | `R` command + base64 |
| `evaluate` | `$addr` → byte read; register name → value |
| `disconnect` / `terminate` | Stop poll thread, `BYE` |

Poll thread: fires `StoppedEvent{reason:"breakpoint"|reason}` on running→stopped transition.
